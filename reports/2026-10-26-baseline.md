## 摘要

這是本 repo 的第一份基準報告，確立「每個數字都可追溯到官方端點」的原則。

**三份報告**：
- 📊 **基準報告**（本檔）— 量化格式分佈、生態體量統計、ChatArt 動態、對本機的建議
- 📄 [論文深度整理](./2026-10-26-papers.md) — 87 篇 arXiv 論文逐篇摘要
- 🏢 [廠商與框架動態](./2026-10-26-vendors-frameworks.md) — 10 家廠商 + 14 個框架的版本動態

七個關鍵發現：

1. **Agent 生態的體量已超越模型本身** — OpenClaw 393k stars、Anthropic 官方 Agent Skills 184k、superpowers 305k、Claude Code 153k。Skill 已成為獨立的一等公民，不是附加功能。
2. **MCP 完成規格世代交替** — `2026-07-28` 為 stable 版，官方 servers 從 legacy era（v1.0.0）完整遷移到 modern era（v2.0.0）。
3. **GGUF 是本地部署的絕對主流量化格式** — 在 608 個熱門模型 repo 中佔 32.4%，遠超 MLX (5.4%)、NVFP4 (3.3%)、FP8 (1.5%)、AWQ (0.7%)。
4. **社群 fine-tune 的下載量仍低於官方量化路徑** — 本機跑的 `HauhauCS/...-Aggressive-MTP-GGUF` 有 231 萬下載，但 `unsloth/Qwen3.8-27B-GGUF` 官方 GGUF 有 586 萬、`ggml-org` 官方 226 萬。
5. **MiniMax M3.1 確實存在** — Ollama 官方 library 已收錄 `minimax-m3.1-flash`，而本機 `config.yaml` 仍指向 `MiniMax-M3`（fallback `M2.7`）。
6. **低精度 KV cache 從「實驗性開關」變成「預設路徑」** — vLLM 讓 NVFP4 走遍 SM8x/12x/90，GLM-5.x 在 SM100 預設改用 FP8（KV 記憶體減半、吞吐 +2.3~5.5%）。
7. **「Harness」正式成為獨立研究對象** — TraceTrial-Bench 實測 3,420 次執行，**31.1% 的 run 在「任務成功但至少一項 harness 準則失敗」** — 只看任務成功率會掩蓋 harness 缺陷。

## 2. Local LLM 與量化

### 2.1 量化格式分佈（608 個熱門模型 repo，HuggingFace API）

| 格式 | 數量 | 佔比 | 適用情境 |
|---|---:|---:|---|
| (無量化標記 / base) | 325 | 53.5% | 官方原始權重，通常是 BF16/FP16 |
| **GGUF** | **197** | **32.4%** | llama.cpp / Ollama 生態，通用性最高 |
| MLX | 33 | 5.4% | Apple Silicon 專用 |
| NVFP4 | 20 | 3.3% | NVIDIA Blackwell 硬體原生 4-bit |
| BF16 | 10 | 1.6% | 訓練/基準用全精度 |
| FP8 | 9 | 1.5% | Hopper+ GPU 推論 |
| QAT | 7 | 1.2% | 量化感知訓練（Google gemma-4 走這條路） |
| AWQ | 4 | 0.7% | vLLM 生態，4-bit weight-only |
| INT8 / 4bit / MXFP4 | 各 1 | ~0.2% | 少量 |

**結論**：GGUF 是本地部署事實上的唯一通用選擇。MLX 只在 Mac 上有意義，NVFP4/FP8 需要特定硬體，AWQ 只在 vLLM 生态。

3. **生態整合**：ChatArt 自己的模型被包成 [ChatArt Skill](https://github.com/chatart-ai/skill)，可安裝進 OpenClaw、Claude Code、Cursor、Codex、Copilot CLI、Antigravity、Coze

### 5.2 十個核心趨勢

1. **量化從「方法競賽」轉向「部署導向的系統工程」** — MpFA（B200 吞吐 2.81x）、FuTransformer（Llama-3.1-8B 每步 2.8ms）、FIGFLEX（每面積吞吐 1.56x）都附帶真機 kernel 測試。另一條主線是去特例化：JustQuant 主張 4-bit activation 不需 smoothing/SVD/rotation，Disaggregated Quantization 主張 prefill 與 decode 該用不同格式。
2. **低精度從「推論期」反攻「訓練期」** — NVFP4/MXFP4 已能撐住大規模 pre-training 與 RL，關鍵在分層精度配置、去偏梯度估計、跨引擎數值一致性。
3. **KV cache 是系統設計主戰場，議題從「怎麼壓」轉向「怎麼搬、怎麼排」** — 更有價值的是負面結果：*When the KV Cache Is Slower Than the GPU* 用 83.32s p99（GPU 僅 7% 忙碌）證明「命中未必勝過重算」。
4. **推論效率的終點是「排程與模擬」** — BLIS 用純 CPU 模擬器以 6.7% 誤差、200 倍速度做部署規劃並合入 llm-d。
5. **PEFT 重心從「新 adapter 變體」轉向初始化的幾何結構、套用的位置、與推論系統的耦合** — GDLoRA 證明 LoRA 可达梯度空間恰等於其切空間；LS-LoRA 證明層選擇比全層適應有效。
6. **「Harness」正式成為獨立研究對象** — TraceTrial-Bench 實測 3,420 次執行，**31.1% 的 run 在「任務成功但至少一項 harness 準則失敗」** — 只看任務成功率會掩蓋 harness 缺陷。
7. **Agent Skill 生態進入「管理與退場」階段** — SkillClash 揭示兩個 skill 同時進 context 會規則遵循率從 93-99% 掉到 61-62%（takeover 現象），主因是 worked example。
8. **記憶管理的重心轉向「何時存、何時取、何時忘、付多少錢」** — MemoryTax 實測：agent memory 對弱模型是昂貴補丁，且**記憶有天花板 — 由寫入它的模型決定**。
9. **Context 管理從「摘要」升級到「KV cache 操作」與「compaction 代價量化」** — Compact-Bench 實測 **LLM 摘要只保留 16.0% recurring detail，機械式抽取可達 79.1%**。
10. **多 agent 協商從「能不能共識」轉向「共識如何形成、誰在主導、權限如何劃界」** — Show-Up Attack 實測 6 個前沿 LLM 全部可被攻破，GPT-5.6-Sol 作為 supervisor 時 ASR 0.93。

### 5.3 三個對本機最直接相關的發現

- **PACT (2610.25048)** — 針對消費級 GPU 上 fine-tune 的真正瓶頸（凍結 projection 昂貴、activation 才是記憶體主體），在 **16GB RTX 5080** 上做到記憶體更低、速度更快。
- **SpecQuant (2609.21704)** — 從同一份 base model 衍生 INT4/FP8/FP16 變體動態路由，**Qwen2.5 取得 35-43% 加速、準確率退化不超過 2%** — 這正是你「一個 base model 跑多個量化」的可行架構。
- **TierKV (2609.21172)** — 手機 long-context LLM 的三層 KV 快取，prefill 吞吐最高提升 17.6x — 如果你未來真的買那台 128GB 筆電，這類技術會直接受益。
